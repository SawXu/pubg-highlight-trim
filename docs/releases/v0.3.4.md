# v0.3.4

这是 `v0.3.3` 之后的一次 Windows CLI 与原生桌面 UI 更新，重点改进了多文件处理、OCR 扫描性能、合并输出可靠性和发布产物。

## 亮点

- 新增原生 Windows 桌面 UI。UI 基于 WPF，不包含浏览器运行时，启动时会连接同包的 CLI bundle。
- UI 支持选择文件夹或一个/多个 MP4，配置检测目标、游戏语言、剪辑前后时长、扫描模式、并行任务、仅扫描、合并输出、递归搜索和覆盖输出。
- UI 运行期间显示逐文件 OCR 进度、保留/跳过数量和原始 CLI 日志；任务可以取消，完成后可以打开输出目录或播放合并视频。
- CLI 新增显式多文件输入，可按 PUBG 文件名中的录制时间从早到晚处理并合并多个视频。

## CLI 变化

新增参数：

| 参数 | 说明 |
| --- | --- |
| `--files FILE [FILE ...]` | 只处理指定的 MP4 文件，并按文件名中的录制时间排序。不能与位置参数同时使用。 |
| `--jobs auto\|N` | 控制并行 OCR worker 数量。`auto` 根据源文件数量、CPU 和可用内存选择 1 或 2 个 worker；`1` 可关闭并行。 |
| `--verbose` | 输出启动设置和第三方 OCR 诊断。默认模式会抑制依赖库噪声。 |
| `--no-brightness-gate` | 关闭粗扫描前的 OpenCV 亮色描边文字预筛选。 |

默认行为变化：

- 文件夹和多文件输入默认生成合并 MP4；单文件输入仍默认不合并。
- 默认合并文件现在放在输出目录内。文件夹或多文件输入使用 `pubg_highlight_trim_output\\pubg_highlight_trim_merged.mp4`，单文件输入使用对应的 `<stem>_pubg_trim_clips\\<stem>_pubg_trim.mp4`。
- 多文件输入必须全部是 `.mp4`，并且合并输出路径不能覆盖任一输入文件。

## 性能与检测

- 粗扫描前增加 OpenCV 文字门控：先检查相对区域 `x=0.26–0.74, y=0.635–0.725` 中的亮色文字、深色描边和水平文字结构；没有疑似事件文字的帧会跳过 PaddleOCR。
- 文字门控只用于粗扫描，事件精修仍使用完整 OCR；对局结束源文件会自动绕过门控，避免结算遮罩压暗文字导致漏检。需要兼容特殊画面时可使用 `--no-brightness-gate`。
- 多视频 OCR 扫描支持并行 worker；worker 间复用 OCR 后端模型，并缓存同一视频和时间点的 OCR 结果，减少重复加载和读取。
- 冻结的 PyInstaller 构建补齐 multiprocessing 启动支持，并抑制 worker 及第三方库的标准输出和错误输出，提升打包版运行稳定性。

## 合并与日志修复

- 修复多个 Highlight 片段的合并顺序，改为按录制时间顺序合并，而不是按文件名字典序合并。
- 修复默认合并文件与输出目录分离的问题，并保留显式 `--merge <path>` 覆盖路径的能力。
- CLI 默认输出现在只保留应用自身的进度、处理结果和摘要；需要依赖库诊断时使用 `--verbose`，耗时明细仍可通过 `--profile` 查看。
- 扫描阶段输出机器可读的 `PROGRESS {...}` 行，结束时输出 `SUMMARY {...}` 并写入输出目录中的 `summary.json`。错误以 `ERROR ...` 形式返回，重定向输出时统一使用 UTF-8。

## Windows UI 与发布产物

GitHub Actions 会在推送 `v*` 标签或手动触发时构建并测试 UI，然后发布两个 Windows x64 压缩包：

- `pubg-highlight-trim-windows-x64.zip`：CLI、内置 `ffmpeg.exe` / `ffprobe.exe` 和 PaddleOCR 模型；无需安装 Python。
- `pubg-highlight-trim-ui-windows-x64.zip`：自包含的原生 WPF 单文件 `pubg-highlight-trim-ui.exe`，并在同级 `cli\\` 目录中携带完整 CLI bundle；无需安装 .NET 或 Python。请保持 `cli` 目录与 UI exe 同级。

UI 构建会验证 PerMonitorV2 高 DPI 清单，改善 Windows 高缩放比例下的显示。UI 也会先检查同包 CLI 的版本和可用性；开发或兼容性测试时可通过 `PUBG_HIGHLIGHT_TRIM_CLI` 环境变量覆盖 CLI 路径。

## 升级注意事项

- CLI 用户直接替换为新的 CLI 压缩包即可。若脚本依赖日志文本，请优先解析 `PROGRESS` / `SUMMARY` 行；默认第三方 OCR 噪声已关闭，需要详细诊断时加 `--verbose`。
- 多文件调用使用 `--files`，不能同时提供位置参数；所有显式输入都必须是 `.mp4`。依赖旧合并文件路径的脚本需要更新，或使用 `--merge <path>` 指定路径。
- 资源受限的机器可显式设置 `--jobs 1`。UI 压缩包中的 `cli` 目录不可单独移走，否则 UI 无法找到后端。
- 本版本的 Python 包元数据、CLI `--version` 和 UI 项目版本已同步为 `0.3.4`，与 `v0.3.4` 标签一致。

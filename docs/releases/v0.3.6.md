# v0.3.6

这是 `v0.3.5` 之后的一次架构级更新：应用程序本体、OCR 引擎与保障工具链从 Python 迁移到 Rust。CLI 参数、WPF GUI 和报告字段保持兼容，发布包则不再包含任何 Python 或 Paddle 运行时。

## 亮点

- 事件解析、扫描、图像预处理、媒体处理、剪辑规划、缓存、报告与并行 worker 全部由 Rust 实现；CLI 直接调用 Rust OCR library，`ocr_engine.exe` 只保留为独立 JSONL 推理诊断工具。
- 发布压缩包不再包含 CPython、PyInstaller、Python OpenCV/NumPy 或 PaddleOCR/PaddlePaddle。默认包为 `pubg-highlight-trim.exe` + PP-OCRv6 ONNX 模型 + 内置 FFmpeg/FFprobe。
- 官方测试、构建、CI 与发布流程改为 Cargo + PowerShell + .NET，可在干净无 Python 的 Windows 主机上完成。
- 项目自有 Python 源码、测试和脚本在 Rust 替代建立后移除，能力与检查映射见 [Python 退休审计](python-retirement-audit.md)。

## CLI 变化

新增参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--split-merge-by-target` | 关 | `--target both` 时按“自己倒地 / 我的击杀”分别生成合并视频；每个源文件仍只扫描一次，没有某类事件时不创建该类空视频。显式 `--merge <path>` 会追加 `_self-death` / `_own-kill` 后缀。 |
| `--move-originals` | 关 | 运行结束后把产生了片段的源视频移动到 `<output>/originals/`，并写入 `moved_sources.csv`；重名自动加 `_N` 后缀，单个文件失败只告警不中断，`--dry-run` 从不移动。 |

环境变量：

| 变量 | 说明 |
| --- | --- |
| `PUBG_OCR_MODEL_DIR` | 指定已有 OCR 模型目录，省略时使用包内 `ocr_models`。 |
| `PUBG_OCR_PROVIDER` | 选择推理 provider（CPU 或 DirectML 构建中的 DirectML）。 |
| `PUBG_OCR_DIRECTML_DEVICE_ID` | 选择 DirectML 设备序号。 |
| `PUBG_OCR_THREADS` | 限制 OCR 推理线程数。 |
| `PUBG_HIGHLIGHT_TRIM_FFMPEG_HWACCEL` | 显式启用 FFmpeg 硬件解码；失败时回退软件解码。 |
| `PUBG_HIGHLIGHT_TRIM_FFMPEG_DIR` | 指定 FFmpeg/FFprobe 所在目录。 |

已移除：`PUBG_OCR_BACKEND` 与 `PUBG_OCR_ENGINE` 不再切换后端，Paddle 后端不再提供。

## 输出与报告

- 报告新增 `merge_outputs`，列出所有按目标拆分后的合并视频；旧字段仍指向第一个输出，保持既有消费者兼容。
- 归档原片会写入 `moved_sources.csv`（`Name`、`SourcePath`、`ArchivePath`），`summary.json` 新增 `originals_dir`、`originals_moved`、`originals_failed`。
- 无法读取的视频现在是独立的 SKIP 结果：单个文件 ffprobe 失败或解码失败被标记为 `unreadable`，不再让整批扫描失败，也不会被误报为“没有匹配事件”。

## 检测修复

- 跨源重叠去重：只有事件身份一致且全帧重叠区域发生变化时才跳过重复事件，并保留上下文更完整的源文件；重复跳过在生成片段前记录（#64）。
- 自己死亡事件的玩家身份与前置 HUD 行隔离，避免把上一条 HUD 的名字或时间串到自死事件上。
- 恢复部分漏检的 OCR 事件，并在对局结束源文件上正确推断语言。
- 亮色描边门控默认改为 `light` 模式，减少细单行事件文本被误拦。

## OCR 引擎与媒体

- 新增 Rust OCR CPU ONNX 基线，并可选构建 DirectML provider（#54）。
- OCR 帧读取改为内置 FFmpeg 解码（#49、#50），支持显式启用硬件解码，失败自动回退软件解码（#52）。
- 干净离线 Windows 包加固：启动时校验模型 hash，运行时不会下载任何资源。

## 图形界面

- 新增“归档原片”复选框，绑定 `--move-originals`，提示文字说明源视频会被移出原目录。
- 结果提示区分“视频无法读取”和“扫描完成，没有匹配事件”（#74），并对不可读文件给出明确计数。
- 仍为无浏览器运行时的 WPF 应用，自包含 .NET 运行时，必须与并列的 `cli\pubg-highlight-trim.exe` 放在同一目录。

## 一致性校验与验收

- 冻结的旧 CLI / 规则 / 媒体基线在 Rust 下重放，95 个私有源片全量差异比对与原始文件完整性校验通过；实测耗时差异已显式记录，详见 [迁移验证](rust-migration-verification.md)。
- 第三方许可与供应链清单由 `xtask` 生成，`THIRD_PARTY_NOTICES.md` 随包更新。
- CI 与发布流程新增 FFmpeg 下载锁（`scripts/ffmpeg-lock.json`）、release 产物复用（`scripts/build_rust_release.ps1`）和 Windows Rust 检查缓存（#76），契约见 [Windows CI 说明](rust-windows-ci.md)；发布流水线在干净无 Python runner 上构建，并断言 CLI/UI 压缩包中不含 Python/Paddle 运行时名称。

## 升级注意事项

- 依赖 Paddle 后端的环境需要迁移：不再有回退路径，`paddle-*` 检测标签与报告字段仅为历史消费者兼容保留。
- 依赖逐段视频路径的脚本仍应读取 `<output>/clips/`；按目标拆分合并后，请读取 `summary.json` 的 `merge_outputs`。
- `--move-originals` 会移动而非复制原始视频，首次使用前请确认输出目录所在磁盘空间和归档策略。
- 本版本的 CLI `--version` 与 UI 项目版本已同步为 `0.3.6`，与 `v0.3.6` 标签一致。

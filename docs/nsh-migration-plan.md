# NSH 迁移计划

> 本文是实施计划，不是实现承诺；本轮只记录计划，不创建 ADR、Issue 或测试。
> 依据：`docs/nsh-migration-assessment.md`、`docs/agents/domain.md` 及相关安装/发布路径的只读核对。

## 已定决策

1. 目标是纯 Rust NSH Win32 原生 UI，关闭默认 WebView2 路线，并在干净环境验证没有 WebView2 Runtime 依赖。
2. OCR CLI、协议和 Job Object 保持独立；迁移 UI 不改变 OCR 算法、参数、任务进程树或取消语义。
3. 直接复用现有 Rust 模块接口，不复制 13 个 IPC 命令；在 NSH seam 上做一个更深的 UI 适配模块。
4. 保留 NSIS 安装事务，只调整 WebView2 相关的发布契约、预检和产物清单。
5. 首版以行为等价为目标，不以像素等价为目标；拖放不捆绑在首版迁移中。
6. 先做旁路 PoC；正式切换前保留 Tauri 发布，但不把长期双轨作为产品方案。
7. 最终发布单个 Windows x64 安装包；既有 System 与 Fixed 安装必须支持原地升级。
8. 升级保留既有 `data` 及卸载数据策略；Fixed 文件只按旧 ownership manifest 处理。
9. 新 UI 必须有真实安装前检查，不得把旧 WebView2 探测改成无操作的 no-op。
10. 支持范围为 Windows 10 1809+ 与 Windows 11 x64。
11. 性能和体积只做同条件 A/B，不预设数值收益；是否有收益由证据决定。
12. 任务进程树、IME/键盘/NVDA、升级能力是硬门；任何一项失败不得正式切换。

## 不得擅自承诺的事项

- 不把旧浏览器 data 视为可删除的 runtime，也不因移除 WebView2 而递归清理它。
- 不承诺新版本降级到旧版本；若产品确需降级，另行评审数据与 ownership 语义。
- 不宣称权威数据动作已经核实；删除、迁移或转换动作须先获得来源和实测证据。
- NSH 0.x 的长期接口稳定性、像素级一致性、拖放和辅助功能完整覆盖均是待验证项。
- 是否保留旧安装目录中的非 manifest 文件、是否提供显式数据迁移入口，若影响产品行为则标为待评审。

## 目标接口与运行约束

- NSH UI 只负责展示状态、采集输入、发起用例并接收权威状态；业务规则继续位于现有 Rust 模块。
- 复用 `service`、`protocol`、`process`、`options`、`storage` 及现有 Job Object 语义，避免第二套状态机。
- 启动前冻结危险参数快照，校验、确认和启动必须使用同一快照，防止确认竞态。
- 启动、取消、退出和状态读取不得在 UI 线程等待共享 Mutex；使用后台任务和明确的状态回传。
- 启动后先保证任务进入 kill-on-close Job，再恢复执行；取消不能退化为只杀直接子进程。
- 运行中关闭必须先进入确认/清理流程；只有权威终态或明确清理失败才能释放停止闩锁。
- 显式设置 `close_on_press=false`，绕过默认关闭等待 250ms；异步清理完成后再显式关窗。
- 大量日志、慢启动、启动失败和清理失败时窗口仍须响应，并显示可区分的最终状态。

## 分阶段实施与退出标准

### 0. 基线与旁路准备

- 固定 NSH 版本及 Rust-only feature，记录 `cargo tree -e features`、工具链、许可证和版本源。
- 建立现有 Tauri 行为基线：13 个命令对应的输入、错误、取消、日志、输出目录和退出语义。
- 定义同一 CLI、媒体、模型、构建模式和机器上的 A/B 采集格式；不先写收益阈值。
- 退出标准：基线可复核，旁路入口不改变现有 Tauri 构建、发布和安装事务。

### 1. NSH 核心 PoC

- 实现路径/目录选择、配置校验、进度、日志、取消、错误、打开输出目录和关闭确认。
- 先覆盖正常完成、取消、异常退出、启动失败、真实关窗和清理失败；拖放明确排除。
- 用一个小而深的 NSH 适配接口承接现有用例，不复制 IPC 命令或业务实现。
- 退出标准：真实 CLI 的任务进程树和 Job 清理证据完整，所有终态可达且无遗留进程。

### 2. Windows 交互与硬门

- 在 Windows 10 1809+、Windows 11 x64 覆盖 DPI、多显示器、中文/空格路径和焦点。
- 真机验证中文 IME、键盘导航、关闭确认、NVDA/UI Automation；toast 不可访问时列出替代反馈。
- 在没有 WebView2 Runtime 的干净 Win 上启动、运行和退出，保存依赖树、进程树和运行日志。
- 退出标准：硬门全部通过；任何 UIA、IME、键盘、任务树或无 Runtime 失败都回到 Tauri。

### 3. A/B 与发布契约

- 比较冷/热启动、内存、UI 构建产物、完整安装包体积和安装后占用；区分固定 CLI/模型/ffmpeg 成本。
- 许可证来源、版本源、NSH/Cargo 锁定版本和发布产物必须可追溯；缺失声明时 fail-fast。
- 由单一 x64 EXE 安装包承接发布；不再把 WebView2 System/Fixed 作为新 UI 的两种发布产物。
- 退出标准：无 Runtime、行为硬门、A/B 证据和产物清单齐全；收益可以为无显著变化。

### 4. 安装、升级与切换

- 保留 NSIS 管理员事务、目标桌面用户预检、ACL、目录锁定、注册信息、回滚和卸载保留 data。
- 旧 System/Fixed 均按原地升级矩阵验证到新包；检查目录、注册、data、日志、输出和卸载后的保留策略。
- 迁移时仅处理旧 ownership manifest 列出的 Fixed 文件；未知或用户文件保留并报告，不按目录递归删除。
- 新 UI 的安装前检查应真实判断新包可运行条件，并在失败前保留旧安装和事务恢复路径。
- 退出标准：干净 Win 安装、旧 System 升级、旧 Fixed 升级、占用/失败回滚和卸载矩阵均有证据。

## 失败处理与发布顺序

- PoC 或硬门失败：继续发布和维护 Tauri，不把失败伪装成新 UI 的兼容模式。
- NSH 切换失败与安装事务失败分开处理：前者是产品路线回退，后者必须由 NSIS 事务回滚并保留旧文件/data。
- 正式切换前继续保留 Tauri 发布入口作为回退保障；切换通过后再移除旧入口，避免长期双轨。
- 任何失败日志、recovery 目录、产物 hash 和构建提交都应保留，不能用“未发生”替代回滚证据。

- 依据已验证的架构和安装决策，再新增一份 ADR；不要在计划阶段预先创建 ADR 或 Issue。
- 切换后补充 NSH 行为验证、无 Runtime 证据、A/B 结果和 System/Fixed 升级记录；未核实项继续显式标注。
